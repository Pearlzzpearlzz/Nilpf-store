2026-06-12 — Mr. IR Repair Note: ILH Entry Screening Gate / Home Redirect Issue

Issue:
ILH Entry Screening kept returning to Home even after the /screening route was patched.

Cause:
The live Add Participant / ILH start buttons were still pointing to /add_participant.
The /add_participant GET path redirects home, so the user never actually entered the intended /screening eligibility gate.

Repair:
Updated ILH start buttons:
- templates/dashboard.html
- templates/packet_builder_select.html

Changed Add Participant start links from:
  /add_participant

To:
  /screening

Current intended ILH flow:
ILH start button → /screening → Entry Screening
0 or 1 No answer → PASS → create participant/member PID → continue to Independent Living Disclosure
2 or more No answers → NOT ELIGIBLE → stop → retain screening record → no participant/member PID

Important:
Entry Screening is the ILH eligibility/fit gate. It is not a normal ILH packet form.
Failed ES records are retained, but no participant/member PID is created.
Passed ES creates the PID and continues into the ILH form path.

Proof-of-function to test after deploy:
1. Click Add Participant / ILH start button.
2. Confirm URL is /screening.
3. Submit ES with 0 or 1 No.
4. Confirm redirect to /independent-living-disclosure/<pid>.
5. Submit ES with 2 or more No.
6. Confirm Not Eligible page and no PID creation.


2026-06-12 — Mr. IR Repair Note: Entry Screening / ILH PID Form Conversion

Issue:
Entry Screening kept looping through the wrong path because ES was treated partly as a hardwired eligibility gate and partly as an ILH form.

Final decision:
Entry Screening is now the first ILH PID form, similar to Intake in other programs.

Correct ILH flow:
Add Participant → assign PID immediately → open Entry Screening → save name into PID record → apply 30-question ES rule → continue or stop.

Eligibility rule:
0 or 1 No = passed → continue to Independent Living Disclosure.
2 or more No = not eligible → stop ILH path, retain ES record under PID.

Important repair points:
- Add Participant now creates PID immediately.
- Add Participant redirects to /entry-screening/<pid>.
- CORE_DOCS_BY_PROGRAM["ILH"] now starts with Entry Screening & Self-Determination.
- ES saves into participant["forms"]["entry_screening"].
- ES name field is editable only when PID name is blank, then locks after name is saved.
- Do not route ILH Add Participant to /screening unless intentionally restoring the old pre-PID gate.
